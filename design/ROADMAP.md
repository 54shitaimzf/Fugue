## 1. 版本号的语义

| 一跳 | 什么时候跳 |
|---|---|
| **补丁位（+0.0.1）** | 一次收口一跳：维护性收口——修复缺陷 · 性能 · 内部机制 · 测试 · 文档 · 归档 · 只增不改既有用法的小改进（`--version` 那一类）。**这是最小单位，没有比它更小的版本** |
| **次版本位（+0.1.0）** | 用户可见的新能力 · 行为变化 · 或性能档位的**量级跃迁**（一个阶段的收口） |
| **1.0.0** | 第一版收口（架构 § 20 八步 · 归档 § 5.1–5.20 的终检） |
| **2.x** | 原生宿主时代（Rust 宿主内嵌 JS face） |

> **补丁位语义的通融（人批 2026-10-01，随 0.2.3 维护批）：**「用户面行为不变」放宽为「维护性收口」——
> 修复缺陷（错的那条路径上行为当然会变，它本来就是错的）与 `--version` 这类只读查询开关都归补丁位；
> 次版本位仍留给「用户可见的新能力 · 工作流变化 · 量级跃迁」。
> **改主意条件**：某一版要求用户改配置或改用法才能继续用——它就不是补丁位，报人。

版本只在收口点跳（既定政策）；CHANGELOG 跟版本走；每版收口交两样：**一条验收读数 + 提交序列**。
读数一律取在一等档主机（ext4）上。**本机取数记两杆**：墙钟（连起跑前与收尾的 `loadavg` 一起记）与**子进程 CPU 秒**（同一趟的 `cutime + cstime`）。宿主忙时同一棵树的 fast 组墙钟能涨四成以上（安静段 36.0–38.5 s 对占掉一半逻辑核时 51.9–53.1 s），CPU 秒同期只涨一成出头——**「套件悄悄变慢」看 CPU 那一杆**，墙钟只作趋势与取数条件的记录。

## 2. CI/CD：一条入口 · 三档节奏 · 零凭据

**CI 已经在跑**：代码仓在 GitHub 上，`.github/workflows/test.yml` 已经在每条分支的 push 与
PR 上跑全量套件；`bwrap` 与 userns 装在 runner 一侧，属于 runner 的环境；仓库侧零依赖零安装。
0.2.2 做的是把这一条路**分成档**。

**三档里的每一档，本地都有一条命令能复现**：测试入口是 `node tools/test-entry.js`，文档校验是
`tools/check-*.js`；workflow 只是搬运工，路只有本地这一条。它是哨兵，不承重：它停掉的那一天，
本地照跑照绿，地板照旧。变异审计这类一次性的重工具只住在 nightly 的审档那一档——自写零依赖（`tools/mutation-audit.js`，
不在 runner 上现取），**不进 `package.json`**；仓库侧零依赖，CI 也不例外。

| 档 | 触发 | 跑什么 | 挡合 |
|---|---|---|---|
| fast | 每次 push | fast 组 | 挡 |
| full | PR | fast 组 + real 组 + 计时读数存 artifact | 挡 |
| audit | nightly | 全套兜底 · 变异审计（看哪个断言抓不住改动）· 长 fuzz · 索引重建等价 | 不挡——只报 |

**边界四条**：

1. **零凭据**：CI 永不携带凭据、永不真出网（发布上传的 token 除外）；real 组的出网测试留在
   人手边，读数进提交序列。
2. **CI 计时只作趋势与回归哨兵**：runner 不是一等档主机；进架构的常数一律取本机 ext4 读数
   （§ 1 末句）。
3. **分组看依赖性质**：真的起进程、真的占端口、真的挂载，才算 real 组，其余全在 fast 组
   ——文件放在哪与分组无关，按文件分迟早漂。
4. **结构跟着读数走，读数到了才建**：PR 先全量；墙钟超过门槛之后，「分片片数」与「受影响
   范围」（import 图纯文本扫描）两个手段按读数逐个启用——nightly 永远全量兜底。
   windows/macos 通道只在发布目标存在（1.1.0）后开。

文档仓自己也有一条：`check-*` 全套逐份跑；跨两仓的 `check-events` 与 `check-ui` 要两个
checkout 同台——能双仓就双仓，跑不了就留本机；**两仓照旧分开**。main 的分支保护与必绿集合随
0.2.2 生效；审查力度两档照旧——接口冻结点开 PR 人审，机械单元攒批 PR 只看断言输出。
**CI 挡在合这一步；写不受拦。**

CD 是 tag 驱动的备货：打 tag 只触发发布那条 workflow（「`test.yml` 不跑标签」这条现行决策
不翻）——0.x 至 1.0.x 备验收读数附件，1.0.4 起 cargo-dist 一条 CI 出多平台产物，1.1.0 出
双包与 Windows 安装包。CHANGELOG 由提交序列生成草稿、人收口；Release 草稿人审后发——**发布
是人的动作，CI 只备货**。

## 5. 阶段三 · serve 与并行（0.4.1 → 0.5.0）

**阶段目标：TUI 零直连 · 一轮多调用的 wall-time 对照 · 门停时人读的是浓缩件。** 归 `T17`（含
`T9` 的前提 · `T14` 的实现）。**前置：设计预期审批三件**——serve 持日志与「单写者 + `round.lock`」
的关系 · 并行工具执行的事件交错形状 · fork 的树形：**单树串行**（只铺一棵树 · 排队用）——
**第一服务目标是纯血 Windows 宿主**（`T19`，§ 8）；Windows 执行落点（`T6`）同形，Linux 侧
退为地板。方向已定，细节随批。审批不过，本阶段不动。

**一张真源、多张脸（2026-10-03 定；服务对象同日修订——客户端与 webui 分开，按「人在哪」划轴）：**
core 只有一份——账本（事件联合）与它的读法；四张脸读的都是它，各服务各的人群：**CLI** 服务
机器与自动化（没有人——管道 · CI · 脚本 · 模型工具调用的仿真，机器是一等公民，不是没装显示器
的二等公民）；**TUI** 服务机器旁的终端居民（工作现场盯着看 · 操作——历史可翻 · 键位不另起炉灶 ·
慢链路省流量）；**客户端** 服务机器旁的图形面人群（**本机轻量**：即开即看的小窗 · 托盘级常驻 ·
门停与收敛的原生通知——轻量买三样：即时 · 常驻得起 · **零网络暴露**（只走本机 serve，一个端口
都不开）；常驻与通知是轻量的后果，不是另立的目标）；**webui** 服务不在机器旁的人群（**远程与
不在场**：隧道那头 · 手机 · 同事机器——零安装是异地刚需；事后审阅人不在时跑的账——地板档是
静态导出页（0.5.1 先例，零服务），远程走 0.4.1「传输可换」那条缝，ssh 隧道不开公网口）。
三条原则：**任何一张脸不开自己的读源**（哪张脸开始自己记一份「它以为的世界」，人群就从共用
一个世界变成各活在转述里——冻结面四张守的就是这条线）· **每张脸对自己的栖息地原生**（CLI 对
管道 · TUI 对终端 · 客户端对本机 · webui 对浏览器——核心不偏爱任何一张脸，每张脸才有资格只为
自己的那群人做到最好）· **流是产品，渲染器是配件**（架构 § 9.8）。**输出形状缺省翻转**（机器读
为缺省 · 人面变显式档）记在 1.x 大版本边界：不做过渡件，条件齐——webui 落地（1.5.0 那一站）· 机器消费者成
CLI 多数派——一次做干净，配破坏性 CHANGELOG。

**分层与职责（2026-10-05 定，总纲五句）**——上面按人群分脸，这里按职责分层：**状态一份**，
会话状态唯一的家是 core 的账本；**功能一份**，动词住在 core（一份**命令值层**：收参数 ·
出值），CLI 与 serve 各是它的一个壳、两边出同一个值，客户端提供入口、不另立功能；**serve 是
协议守门人**，方法面 = 动词 · 事件通道 = 账本尾随，图形与交互那几张脸（TUI · 客户端 · webui）
都走它、无一直连，CLI 是第一张脸、与 serve 共用同一份值层，两条路各自可用；**脸各拥其表**，
呈现归脸，判读永远只有 core 那一份读法；**客户端独占其托**——进程与端点（serve 宿主 · web
端点 · 扫码配对 · 托盘 · 原生通知）外加自己窗口的呈现状态，不多记一行「它以为的世界」。按
「轻」排脸：CLI 连界面都没有、排第一；TUI 住在同一个可执行文件里、零额外包体；客户端与 webui
是两张图形脸——一个是原生小窗，一个是被派发的页面（派发者是端点的宿主，不是页面自己）。客户端
必须轻量由此从偏好升成结构前提：它是这台机器上唯一被批准常驻的进程，一切需要「有人在家」的活
最后都长到它身上——它自己不便宜，「长在客户端上」就不成立。

**宿主档位（web 端点住哪，2026-10-05 定）：**静态导出页**无宿主**（死 HTML，谁都死了它还
能看——这是它当地板的原因）→ **1.5.0 起由 CLI 临时宿主**（端点那一档，
名字随 0.4.2 定——前台跑：终端在它在 · 终端关它死，不引守护进程）→ **1.6.0 客户端接管**（web 端点
与 webui 静态资产搬进托盘进程，扫码配对同搬）→ **远程**照旧隧道指向 localhost，不开公网口。
0.4.1「进程角色与传输解耦」那道缝保证 1.6.0 的搬家只是「端点住在哪个进程里」，不是协议改动。
多端附着（TUI + 手机 + PC 浏览器同时在线）把会话模型顶进 0.4.1 的前置审批：谁附着 · 谁拥有
serve 的生命周期 · 并发事件怎么交错。
