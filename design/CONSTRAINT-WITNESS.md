# C 区诊断的具名见证

路线图 § 10 已明确：`运行时上下文` 积累，后面的 `信号摘要` 与 `上一步结果` 逐步替换。只拿上一份拼好的 `Prefix.zoneC` 作前缀比较，会把普通非静默步骤新增的轮次报成「中部被改写」。这不是修改发送字节或 U18 裁断规则的理由。

诊断调用方可在装配时，从**同一份段值快照**和该次 `Prefix` 调用 `constraintWitness(protocol, segments, prefix)`，保存返回的具名见证。下一次诊断把它作为 `checkConstraints` 的第七个参数传入，前六个参数照旧。见证只在内存里供诊断使用；不进 `Prefix`、日志、模型请求或协议字段。

见证拥有三个 C 段渲染后的字节，并绑定它们的顺序与渲染器。只有既有三段顺序、运行时文本渲染器、完整段值与完全相符的装配字节才能建立见证。检查时再验证上一份 C 字节、当前段序/渲染器和当前装配字节。未知对象、缺段、改序、换渲染器或字节不符均回到原整段 C 的诊断，不免除只追加检查。调用方仍负责传入同一条 agent 会话上相邻两步的快照。

具名比较使用运行时文本渲染的正文，只移除 `text` 渲染器增加的**一个**结尾 LF。正文已有的 LF 保留；空正文和原先没有结尾 LF 的正文可以追加。积累正文的删除或中部修改仍报 `append-only`，位置指向 `运行时上下文` 的 UTF-8 字节。后两段可正常替换，但绝对路径、环境身份和 Signal 原文三项仍逐段检查。

这份见证来自调用方明确交付的段边界；不从未转义的 C 文本猜测边界。只有裸 `Prefix` 的旧调用继续给出整段 C 的粗读数。运行时、装配接口和发送路径均未接入新检查器，实际 A/B/C 字节与工具目录没有改动，因此本单元不声称重录了模型调用或支付了新前缀。

- `node tools/test-entry.js real src/assemble/constraints-state.test.ts src/assemble/constraints-live.test.ts`：真实 Git 状态和 M0 的非静默步骤；保留裸 C 的粗读数，同时证明具名追加不新增违反、真正改写/删除仍报错。真环境的宿主名/pid 与真实方针文字的偶然碰撞继续按现有诊断报告，不用受控 facts 的零违反掩盖它们
