## 2. 形态已经收敛的两条

### 2.1 T1 代码图与符号级写入面

| 实现 | 机制 | 证据强度 |
|---|---|---|
| [RepoGraph](https://proceedings.iclr.cc/paper_files/paper/2025/hash/4a4a3c197deac042461c677219efd36c-Abstract-Conference.html)（ICLR 2025） | 仓库级代码图，行级节点 + 跨文件边 | **有公开测量**：作为插件接入现成 agent 即得提升 |
| [CodexGraph](https://aclanthology.org/2025.naacl-long.7.pdf)（NAACL 2025） | 代码图入库，经图查询语言取用 | 同上 |

**证据的形态决定了它的位置**：两者都是在已有 agent 上**加装**插件——图是增量能力，加在**索引**之上，而索引由 `M3` 承担（架构 § 8.16.b）。

**做成什么样：写入面分两层。** 契约的写入面声明从一层变两层——**路径**继续管回收与强制（子进程往外写了哪些文件），**符号**管预检（两个契约会不会碰同一处）。判据随之从「路径集合相交」变成「沿图查影响面」：A 要改的符号，B 会不会碰到，哪怕隔着文件调用。`M11` 仍是一个函数、仍跑两处（架构 § 8.12），派发前与合并前给出的仍是同一个答案。

**为什么值得：路径级两头都不准。**

- **漏判**：A 改 `a.ts` 里 `foo` 的签名，B 改 `b.ts` 里调用它的那一行。路径不相交 → 放行 → 冲突留到不可逆点上才炸。
- **误拒**：A 与 B 改同一个文件的不同部分。路径相交 → 拒绝 → 拆分被迫做到**文件粒度**。

合并本身是**内容级**的：`M13` 做三方合并，同一个文件里不同区域的改动本来就合得下去。判据该逼近「这次改动能不能合下去」。

**安全论证换了一句，如实登记。** 现在的论证是「路径不相交 ⇒ 不会有文本冲突」，那是硬保证；之后的论证是「**不碰同一个符号**」——同一个文件里紧邻的两处改动仍可能撞上。这一类有既有的处理路径（合并报告与冲突解决）；跨文件那一类，路径级从来没有接住过。

**启动的条件**：出现「要并行改同一个文件的不同部分、却被预检拒掉」的拆分。

### 2.2 T6 Windows 作为执行目标

**Windows 进 `M4` 的物化落点，不进宿主：**

```
Linux（真源）                              Windows（派生 + 执行）
  M0 log / M1 git objects
  M2 view ──M4.ensure──► mirror\ ──原生工具链──► 产物
      ▲                      │                      │
      └─── M6.collect ◄──────┴── 仅声明集内的产出 ◄──┘
```

**边界只承载 delta**（架构本就有的性质）：初次全量镜像一次完成，此后每步只同步改动过的文件——走的是 `M4.ensure` 已经算出来的那份 delta（架构 § 8.5），边界不新增工作量。

**代价如实登记：**

| 项 | 变化 |
|---|---|
| 真源（日志 · 对象 · 视图） | **不受影响**——在 ext4，唯一回来的路是声明集（架构 § 22 的 D7） |
| 物化镜像 | 可被 Windows 侧进程破坏；它是派生的、可弃的，重新物化即可 |
| **用户的 Windows 机器** | **越过强制点的覆盖面**：真源在 Linux 侧由 `M7` 守着，Windows 侧只到 `受限令牌` 这一档（架构 § 8.8） |

> 边界能保证「进程弄不坏真源」，不能保证「进程弄不坏你的机器」——**强制点的覆盖面到哪儿，`enforcement` 就如实报哪儿**（架构 § 8.8）。

**一条硬约束**：调用 Windows 的能力只挂在**声明的动作**上——通用 shell 不放行，否则 `/mnt/c/…/cmd.exe` 就是一条绕过一切的路。`RunSpec.action` 本来就取自系统级配置的动作白名单（值域在架构 § 8.12，来源在架构 § 15.3.a），「只跑声明过的动作」是既有性质，Windows 运行器直接继承。

### 2.3 补登记的这四条

`T11`–`T14` 是 § 2.1 · § 2.2 那两条之外、形态还没收敛的四条。写在这里，是为了**不让它们以「没人提过」的形式消失**（`T11` 已立站路线图 0.5.4——0.5.0 读数之后、1.0.0 之前，条件触发；其余三条排期另说）。四者的共同点：不改结构，改**结论的读法**。

- **`T11` 单工具与代码化调用**：它会**移动那笔账的基准**（计划 § 3：地板不是零，是一个小负数）。模型那一侧的动作从一串往返收成一条调用之后，对照的那一侧堆积也会变慢、压缩也会变稀，于是两笔之差要对着一个**更小的基准**重估。方向确定（两边同时变化，差只会变小），幅度不给。所以动它之前，先把对照读数留下来。
- **`T12` 用户原话的留档**：它是**体验层的保证，不是正确性保证**。检索是词法匹配，用户换了说法、只记得大意就查不到；查不到时不编。它不省 token，占的只有环境视图里一行恒定声明。**今天这一条是自觉偏离**——架构 § 9.7 那条分界定的是「模型的动作面进日志，模型自己生成的文本不进」，于是「说漏了还能收回」这句话今天没有着落，代价如实登记在这里。
- **`T13` 整套对整套的对照**：它是「值不值」唯一的判定点（计划 § 4.5）。今天有自己这一侧的八元读数，**只有一侧的读数不叫对照**——别人那一臂的日志格式今天不存在。这一条至今没有人做过。
- **`T14` 模式切换的浓缩件**：它要的是**取信**——摆出可核对的关键细节（几个任务 · 哪几条路径 · 验收是什么 · 与上一次放行的集合差哪几条），让读的人自己核对。人的注意力有限，不会为了批一次拆分去读完整份草案；读不完就只剩「看着像不像」，那不是批准，是把判断放弃了。它不改结构：浓缩件由模板从日志与草案**重算**（架构 § 15.1.a 的「呈现」只覆盖门那一次；进预备态那一次还没有对应的渲染）；它**不许成为第三处真源**，也不许由模型自由撰写——模型只写「为什么这么拆」那一句，其余每一个字都是算出来的。

### 2.4 补登记的这一条

`T15` 与 § 2.3 那四条不同类：那四条改**结论的读法**，这一条是**机制补全**——把 `fugue run` 已有的 cache 落点（架构 § 8.6 的 `cacheRoot(a)`）接进格内。它挂在 W8 的冻结点上（driver 那两句：档取 `workspace-write` · 不绑声明目录），而那两句是按 read-only 时代的实测理由定下的；格内 real 组出现之前不动它，动它先过设计预期审批。

### 2.5 补登记的这一批（2026-10-01）

`T16`–`T18` 与 § 2.3 · § 2.4 那五条不同源：那五条从落地过程里长出来，这三条来自一次外部调研与一手基准（2026-09：竞品三家的搜索与解耦架构 · Node↔原生集成的选型 · 本仓与 /usr/include 的检索基准）。共同点是**都改机制、不改结论的读法**——不动冻结接口，各自可独立收口。基准读数把方向钉住了：本仓 2.78MB 纯 JS 逐行匹配热路径 15ms · `git grep` 搜同一份 blob 13–19ms——慢的原因在机制（零缓存 · 串行往返 · 截断在后），语言只是常数因子；正是架构 § 16 L1 说的那一档差别。`T7` 仍是原生化的唯一轨道，这三条跟着它走。

### 2.6 T19 Windows 作为一等宿主（纯血）

**整套原生住在 Windows 上，真源在 NTFS**——不是 `T10` 的壳，也不是 `T6` 的 mirror：宿主本身。
它是**单树串行的第一服务目标**（用户定 2026-10-02）：退并行化之后，铺一棵树 · delta 同步 ·
排队 · 复位只动改过的路径，每一样 NTFS 都有实现——**退化档就是可移植子集**，纯血 Windows
由此从不可能变成可论证的选项。

**与 `T6` 的关系**：`T6` 仍是跨宿主那一份——真源在一等档 Linux 主机上，mirror 只承载 Windows
专属构建；`T19` 是 Windows 自己当宿主。delta 同步 · 受限令牌执行先在 `T6` 那一侧长出第一份
实现，这里全部复用。

**先要答清的**（阶段四第一格的地基，站序在路线图 § 8）：E1 为 NTFS 立读数——一等档白名单是
量出来的，不是默认的；盘与树比的 Windows 语义差逐条收口——exec 位 · 大小写碰撞 · CRLF ·
打开文件的强制锁；打断与进程组按 Windows 等价物重写；CI 加 Windows 道。

## 3. 版本收口与融入（2026-10-01 定）

版本是**收口点**：每版一条可断言的验收读数，先后由依赖决定（机制先于语言——L1），启动由各条自己的启动条件决定；「由条件决定，不由日程决定」这条原则不因这一节改变。收口次序的展开表（版本号 · 每版改什么 · 验收读数，**0.0.1 为最小单位**）在《[Fugue —— 版本路线图](ROADMAP.md)》——两处只留一份，防漂；三线收口那一站的站序与口径已归档（归档 § 5.20）。

三条登记：

- **`T1` 暂缓**（2026-10-01 用户定）：语义图一档（意图映射）太偏语义、价值未证——总表那一行的启动条件照旧挂着，解除由人批。
