# Native sandbox and tools port

This backend is native Rust on Linux. It never invokes Node for product behavior, changes host security settings, or launches an action without verified isolation. The static tool catalog was extracted from the upstream development oracle; its canonical SHA-256 prefix is `5681832878aa0634` and all twelve tool names, descriptions and public parameter schemas are unchanged.

## What is implemented

- `fork`, `ensure`, `verify-mat`, `dispose`, `diff-stat`, `policy`, configured `run`, isolated shell execution, and all twelve catalog tools
- Immutable Git-object copies, strict branch/base checks, journal-replayed manifests, incremental changed-entry synchronization, unchanged-file inode/mtime preservation during ensure, full-tree drift verification and read-only verification
- Secure directory-FD-relative access, no symlink traversal, no inherited file descriptors, bounded reads/scans/JSON, hardlink refusal, safe internal relative symlink targets, mount-table checks before disposal, per-writer materialization locking and journal writer locks
- Validation of argv, cwd, output/cache declarations, environment names/values, network modes, action schemas and contract write scopes
- Mandatory fresh bubblewrap namespace probe including the actual native Landlock/seccomp guard self-test. An unavailable or failed layer returns a blocked policy or execution refusal; no degraded host-execution path exists
- New mount/PID/user/IPC/UTS/cgroup/network namespaces, no capabilities, nested user namespaces disabled, a read-only root/toolchain/workspace by default, sized private HOME/TMP filesystems, Landlock ABI-6-or-newer filesystem and IPC/signal restrictions and seccomp denial of dangerous syscalls/socket families
- Output validation before reclamation: undeclared, special, hardlinked, escaping-symlink, stale-view, timeout or output-budget failures discard the job outputs and never apply them to the view. Valid outputs are pinned as Git objects and then applied through the core's checked batch API
- Declared action cache directories are separately snapshotted, validated, seeded into the next job, and persisted per writer. They are excluded from Git/view reclamation. Cache declarations overlapping tracked inputs or output declarations are rejected
- `implement.ownedPaths`, `resolve.conflictPaths` and `investigate.evidenceRequired[].artifact` scope enforcement, holder-only questions/plan exits, holder checkpoint/action-output refusal before approval, upstream-shaped `holder/todos`, `holder/ask` and `holder/plan` receipts, UTF-8-aware bounded tool receipts, and bounded linear-time Rust regex search

## Deliberate differences and explicit refusals

1. Copy and real hardlink-ro are supported. Hardlinks use only a private immutable Git-object mirror, with declared RO paths, inode/device/link-count/content provenance checks and detaching COW for changed entries. Mutable host worktree bytes are never linked or imported. Strategy is a preference: unavailable overlay/reflink/hardlink candidates report reasons and fall back honestly. Overlay capability is probed only in a disposable bwrap namespace; no persistent native overlay backend is implemented, no host mount/security setting is changed, and the chosen result never falsely says overlayfs.
2. CLI --ro and API readOnlyPaths are validated, with ambiguous dual declarations refused. preserveMtime/no-preserve-mtime and pruneEmptyDirs are real controls; changeDetector (content-hash|mtime-size) and detectRenames are validated/persisted advisory declarations, as neither is consumed by upstream runtime. Security validation always hashes content regardless of detector preference.
3. Normal file mtimes are preserved at fork when the physical source still has exactly the immutable object's content and canonical Git mode. Dirty/missing sources receive newly created mtimes; clean symlink mtimes are copied without following links. `--no-preserve-mtime` and the API `preserveMtime` boolean are supported. Every ensure preserves unchanged entries, independently of fork timestamp behavior.
4. Changing the branch base across an existing materialization requires a new fork. Invalid or backward revision requests are refused. Gitlinks, special files, absolute/escaping/protected-state symlink targets and layout-colliding writer names are refused.
5. Read-only action declarations must name directories. A tracked file leaf cannot be mounted as a writable output in that mode. Workspace-write mode supports existing and absent leaf outputs; missing parents are prepared without guessing that a new output is a directory. Every changed leaf still has to pass declaration/scope validation before reclamation.
6. HOME and TMP are fresh 64-MiB tmpfs mounts on every invocation. HOME/XDG package-manager caches do not persist implicitly. Only explicitly declared `actions.<name>.cache` directories persist; they retain byte content and mtimes and are never imported into a view. Cached source/output overlap is refused.
7. Host environment inheritance is not supported. `inherit: all` fails explicitly. `core` and `none` both use a pinned sanitized baseline plus explicitly validated configured/injected values; there are no inherited variables for `exclude` or `include_only` to filter. Policy reports the actual `none` inheritance. PATH/HOME/TMP/XDG/PORT coordinates, loader/shell injection variables and Git command/config injection variables cannot be overridden. Environment values are never journaled.
8. Network is absent by default. An explicit action `net: host` shares only the network namespace, while all other sandbox boundaries remain mandatory. This does not enforce per-domain egress filtering. PORT/PORTS use the upstream four-port slice of the configured range and sorted journal-writer index; these are advisory coordinates, not exclusive kernel leases, and adding earlier-sorting writers can change slices.
9. Custom reachable roots are restricted to public toolchain/system locations under the default allowed root set. Broad host root/home/credential reach is refused. The default exposes `/usr` and public system files, including only SSL certs/openssl.cnf. Broad `/opt`, broad `/etc/ssl` and SSL-private reach are refused; an `/opt/<toolchain>` root needs an explicit narrow declaration. Selected installations must be trusted.
10. Grep uses bounded Rust regex. JavaScript lookaround/backreferences and other unsupported regex syntax fail rather than using a potentially unbounded matcher. Advertised read slices, grep glob and grep output modes are implemented. Default read text receipts retain the upstream format; explicit slices include line numbers.
11. The native guard is provided by the running Fugue executable. Library embeddings must route the private guard mode in that same executable; otherwise the probe fails closed. Seccomp supports Linux x86-64 and AArch64; unsupported architectures fail closed. There is no macOS or Windows native execution backend in this port.

## Resource and transaction limits

Limits include 100,000 tree entries, 128 directory levels, 64 MiB per file, 512 MiB total scan/materialization bytes, 1 MiB each captured stdout/stderr stream, a default 60-second action timeout with a 300-second maximum, 64-MiB HOME/TMP mounts, and guard rlimits for core dumps, file size, file descriptors, CPU, process count and address space. Timeout/output-limit failures terminate the process group; bubblewrap's PID namespace and die-with-parent lifetime protect against escaped background descendants.

There are no per-job cgroup quotas. Rlimits are weaker than cgroup memory/CPU/aggregate-disk quotas, and the writable derived workspace can consume disk space before post-run validation. This backend must not be advertised as a complete hostile multi-tenant resource-isolation system. It does not defend against an independently malicious same-UID host process replacing the executable or racing the parent outside the managed workspace policy.

Materialization uses durable mat/fork-ready publication intents and mat/apply synchronization intents, validated staged trees, safe retained old trees, and bounded resume/recovery. Ordinary drift is not treated as an interrupted apply; only known old/new changed entries under the durable intent can resume. Tests inject all five fork-swap phases for both copy and hardlink, plus partial ensure recovery. It cannot alter the user worktree. Reclamation validates the full set and uses checked core batch writes, but the upstream-compatible journal protocol can retain a complete prefix after a crash. There is no claim of all-or-none crash atomicity across journal/Git/cache filesystems.

## Verification on this host

Run `cargo test --manifest-path rust/Cargo.toml --test sandbox_tools` with the configured Cargo/Rustup homes. The suite checks the real native guard probe, accepting successful installation or explicit refusal with no unsafe execution. This host actually refused the guard because Landlock ABI6 is unavailable; successful Landlock/seccomp installation is not claimed. Other tests validate immutable/defensive materialization, tool protocol/catalog/scopes, read-only verification, receipt bounds, cleanup and fail-closed execution. This container denies bubblewrap's namespace setup. The isolated successful action/reclaim/cache/host-network paths are implemented but cannot be exercised here; their success is not claimed by a passing refusal test. No live model or external network requests are made by these tests.


## Toolchain facts and strict positive lane

`sandbox::toolchain` validates declaration/cache shape and probes only trusted public executable/version-argv allowlists with bounded process/output and a cleared environment. Null failures never become a positive cache hit; arbitrary configured shell/argv is not executed on the host. A matching positive reading is reused; writes merge only workspace-level reading fields after configuration consistency recheck.

`rust/tests/isolation_required.rs` contains five explicitly ignored portable-lane positive acceptance cases, invoked by `sh rust/real-check.sh`. These require actual guard installation and isolated action success, new exact-file output/reclamation, declared cache persistence without Git import, outside-write denial, and no-net enforcement. On this host the explicit run failed0/5 (five failures) at Landlock ABI6 unavailability, before action execution. This is a verified environment blocker, not a passing or silently skipped successful-sandbox test. The portable refusal tests remain separate.

Workspace-write absent exact-file outputs prepare parents only, not a fake directory leaf. Validated imports log upstream-compatible mat/reclaim.changed; denied/discarded imports log an empty changed array, so diagnostic metrics remain valid.
