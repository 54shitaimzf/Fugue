# 索引构建：按唯一UTF-16键分配字符串

这是 0.4 验收之前的一笔机制优化，不改变 blob 索引格式，也不启用索引缺省档。
构建仍核完整 Git 内容地址，按 grep 的 UTF-8 解码语义读文本，并保留所有三元组。

原实现对文本每一个位置做一次 `slice(at, at + 3)`，即使它随后只是重复插进 Set。
新实现先把三个 UTF-16 单元装进一个48位整数，用数值 Set 去重，只为最终唯一项
创建字符串。48位小于 Number 的53位精确整数范围；按数值排序等同于三个无符号
UTF-16单元的词典顺序，所以 canonical 编码仍逐字节相同。不能改成 Unicode码点
三元组或UTF-8字节三元组：那会漏掉现有正则匹配依赖的单元窗口。

没有改变64MiB source、200,000个唯一项、8MiB编码预算或超过预算即整体失败的语义。
保留缓存的逻辑项数与canonical字节预算不变。Set 的具体堆布局、boxed number与字符串
成本由runtime决定；这个改动不宣称精确RSS下降，也不把逻辑预算冒充物理内存上限。

## 可复现断言与测量

```sh
node tools/test-entry.js fast src/search/index-builder.test.ts src/search/index-format.test.ts src/search/index-store.test.ts src/search/blob-index.test.ts
node tools/bench-index-components.js
node tools/check-targets.js
node tools/check-events.js
```

新断言把高UTF-16单元、emoji跨代理窗口、NUL、所有字节、非法UTF-8与200份生成语料
同时按SHA1/SHA256核对完整对象及canonical字节。机制断言不测速度，只数源文本上的
三单元slice：新实现0次；未修改父提交的独立负对照是159,998次，明确失败。
已有预算、损坏退档、存储与后台生命周期断言继续跑。

开发脚本是16MiB固定语料（8份2MiB，一半重复代码，一半高单元熵），同进程交替跑
修改前的完整字符串构建参考与新构建各3次、取中位数，每一档核全三元组表。
也分别记可见窗口拷贝、空Worker启动、编码、解码、重建和重复盘读；各项独立计时，
不能相加冒充主查询墙钟。脚本不清OS页缓存，重复盘读不是物理冷盘。

一次Node24.19云overlay读数：混合语料字符串构建中位数合计1,380.711ms，新构建
1,121.747ms（0.812倍）。各文件比值0.563–1.367，有一份高熵语料更慢，不能声称所有
输入都会加速。唯一项分别1,370/约30,001，canonical记录分别8,592/约357,000字节。
另一次重复代码专档2,107.018→1,264.592ms（0.600倍）。共享机器的Worker启动中位数
从49到134ms波动，跨时段的绝对值不能代替同进程对照。

编码/解码与盘读成本、每blob Worker启动、超过LRU容量的重复磁盘解析仍在。
主查询 miss 回扫描、后台准备必须分别报告；本单元不解决它们，也不宣布16MiB冷查询
<50ms、ext4验收或0.4完成。端到端参考/准备读数另由查询矩阵记录，不能用构建比值替代。

## 端到端证据与归因限制

另在查询接线的独立检查点 `bcf0c1ce9570e45428c805fbaf12eeb512e5322d` 上顺序跑相同
Truth/View/grep矩阵（`node tools/bench-index-query.js --runs 1 --files 256 --lines 512`）。
固定16,037,385字节；第二趟只有 `src/search/index-format.ts` 内容哈希变化。各档精确回执
仍与全扫相等，每类准备末都是256次source/构建、256条、零淘汰，逻辑gram/编码字节相同。

显式准备总计134,463.456→104,315.173ms（0.776倍）；dense/sparse/miss分别
30,534.881→32,407.459、51,251.087→30,867.307、52,677.488→41,040.407ms。
dense准备反而更慢；已建盘读的miss也从639.632→1,111.535ms。没有修改盘读路径，
关闭索引的全扫同样波动，所以这是**一次共享机器顺序对照的趋势，不能全归因于builder**。
同进程交替组件对照支持分配成本改善；端到端仍要在一等档多次复测。
256条刚好装进默认LRU，不能据此否认512条反复磁盘解析的已知回归。上述几十秒准备
与大于50ms冷读都不满足0.4激活条件，默认仍关闭。
