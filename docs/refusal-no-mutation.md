# 0.2.6：语义拒绝的统一状态断言

`test/helpers/refusal.ts` 提供 `captureTree(root)` 与 `assertRefusedWithoutMutation(root, view, action, reason)`。后者先保存独立快照，再验证拒绝原因，最后比较同一个根和内存视图的状态，避免只检查某个目标文件而漏掉旁路写入。

记录范围：

- 每个相对路径的存在性、文件／目录／符号链接类型和模式位；普通文件的全部字节；符号链接的原始目标字节。
- View 的完整 `state()`（含 rev）与 `diff()`；使用 `structuredClone`，共享对象或字节数组不能遮住回调造成的变化。
- 根必须是实际目录。逐项使用 `lstat`；链接只读 `readlink`，不递归进入目标。FIFO／设备等不支持的类型明确拒绝，不读它们。

只在由测试独占、初始化已完成的生成工作区调用。快照不比较 inode、所有者或时间戳，不保证并发同 UID 修改期间的一致性。读操作可能改变 atime；它不属于这里的「未变化」口径。

`src/view/edit-refusal.test.ts` 在真实 Git／日志／View 上使用同一断言，根的范围包括 `.git` 对象、日志、写者锁及生成的人类文件／链接。先完成两次合法写入、取得写者锁，再取拒绝前的快照。七个入口分别覆盖：父路径是文件、覆盖目录、下层改名目标已存在、目录改名、删除不存在路径、目录 chmod、链接 chmod。下层改名拒绝还验证 pin 的幂等 blob 写入都未开始。

负对照把 `applyEdit` 的全部语义检查挪到 blob 写入之后，七例中三例变红：两例发现新对象写入，一例发现被拒的下层改名已经调用 `putBlob`。另有五个 fast 用例直接验证快照能发现字节、模式、新路径、文件类型、链接目标、共享内存引用变化及无效 UTF-8 链接目标变化，以及拒绝前磁盘写入；外部链接目标内容不被跟随。

```
node tools/test-entry.js fast test/refusal.test.ts
node tools/test-entry.js real src/view/edit-refusal.test.ts
```

真实 Git 进程按路线图 §2 归 real 档，纯文件／内存快照检查归 fast 档。本单元验证架构 §8.3 的「先问全部，再落任何一行」，属于 0.2.6 的统一拒绝断言增量。它不把已提交日志后发生的 IO 故障算作语义拒绝，也不宣称策略拒绝时合法的 `bound/deny` 审计事件必须消失；其他拒绝入口需要按自身允许的审计范围另行接入。产品代码和日志尾部恢复均不改动，完整维护批次验收仍有独立门槛。
