# 日志围栏的根与持有寿命

`holdWriter` 与 `openLog` 在入口把根解析为绝对路径。之后改变进程 cwd，不会把释放、读取或追加转到另一仓库。相对根调用返回的 `Hold.path` 因而是绝对路径；现有 CLI 已交付绝对根。

一次成功取得的 Hold 保留一个只读私有文件描述符，固定其锁 inode。只存 dev/ino 数字不够：旧名字被移除后，inode 编号可能重新使用。释放在任何清理前标记该寿命已结束；重复调用不再接触文件。第一次释放只有在当前普通锁文件仍指向所固定 inode、记录仍满足原 PID/start 比对时才移除名字。换成另一文件、软链或无法确认的记录均保留；所有释放分支都会尝试关闭描述符。取得失败也关闭已打开的描述符，次要关闭错误不覆盖原拒绝或错误。

这多占每个存活 Hold 一个描述符，直到释放。锁记录的版本、字段、PID/启动时间判活与陈旧锁接管策略不变。临时文件独占创建；打开/初始 fstat 失败只清理已证明同 inode 的自有临时文件，已有或身份不明的名字保留，不作扫描清理。本修复依赖合法写者遵守围栏；名字检查与 unlink 之间不是原子的同 UID 认证协议，不承诺抵抗主动并发改名。

八个文件系统控制覆盖两仓库 cwd 切换、旧对象再次释放、同进程替换 inode、Log 读写根、成功/拒绝的描述符寿命、初始打开/fstat 失败及缺失名字后出现新持者。原源码的前四个控制 0/4；修复后的相关官方 fast 命令45/45，其中八个为新增控制：

`node tools/test-entry.js fast src/log/hold-ownership.test.ts src/log/log.test.ts src/log/tail-recovery.test.ts src/log/maintenance-integration.test.ts`

所有根与替换只在生成的测试目录中。半行尾的读取、追加拒绝及初始化/close 栅栏保留现行行为，事件与记录格式不变。精确组合 head 的 CI 独立记录，不用本地结果代替上游验收。
