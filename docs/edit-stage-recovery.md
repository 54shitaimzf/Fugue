# 0.2.6：视图写入的持久边界

`src/view/edit-stages.test.ts` 为架构 §9.3 的 `blob → 日志 → 内存` 顺序补上七个确定性用例。每例在临时 Git 仓库中使用真实 Truth、日志和 View，只在已有接口返回处注入异常；随后关闭两个后端并重新打开，按完整日志行重建视图，逐字节验证包含中文、NUL 和无效 UTF-8 字节的内容。

| 停点 | 已持久的事实 | 恢复断言 |
|---|---|---|
| `putBlob` 已完成、尚未追加日志 | 一个孤儿 blob | 对象仍可读，活视图和新后端重放均没有新路径 |
| 日志已追加、调用者未收到确认 | 完整 `view/write` 行及其 blob | 原内存未变；重放恢复路径、全部字节、执行位和 rev |
| 日志已确认、尚未应用内存 | 完整 `view/write` 行及其 blob | 内存接缝失败；重放恢复已提交路径 |
| 下层改名／改权限的第一行完成 | 固定原内容的 `view/write` | rev=1，源路径内容被钉在上层；最终操作尚未发生 |
| 下层改名／改权限的第二行完成 | pin 行和操作行 | rev=2，重放恢复最终路径／权限；原内存仍未应用 |

后两项各测 rename 和 chmod。它们有两条独立日志行，不能把 pin 前缀说成原子的整次操作；失败返回也不代表日志没有提交。孤儿 blob 是 §9.3 允许的结果，因此本矩阵不宣称注入故障之后整个仓库未变。

运行：

```
node tools/test-entry.js real src/view/edit-stages.test.ts
node tools/test-entry.js fast src/view/view.test.ts src/view/replay.test.ts
```

负对照在私有副本里把 `applyDelta` 移到日志追加之前，同一七例中六例失败，分别发现提前改动内存或尚未提交日志。产品源码不添加测试专用故障开关。

这是接口边界异常和实际持久前缀的恢复验证，按路线图 §2「真的起进程」的判据归入 real 档。它不模拟电源丢失、设备缓存或每个系统调用中的强杀；已有 `replay.test.ts` 保留跨进程退出／SIGKILL、手工残缺尾行及快照缺失／损坏／过新测试。本单元不改日志尾部修复、快照格式或提交 ref 协议，也不关闭 0.2.6 的完整验收门槛。
