# Existing-runner prepared-cold diagnostic

`node tools/test-entry.js real test/current-cold-benchmark.test.ts` runs a bounded developer diagnostic through the existing test entry. The existing PR full job discovers it automatically. No workflow, runner, installation, CI artifact schema, M0 event, configuration or default-index change is needed. Correctness and mechanism assertions may fail; wall time never decides pass/fail.

The generated fixture is the approved code512 recipe: 512 unique 32KiB files, 128-byte lines containing `dense_hit`, with `rare_hit` only in the final file. Its exact path/byte hash is emitted. Allocation is beneath the checkout, rather than assuming the unrelated system temporary directory has the same filesystem. Seed and complete cohort preparation are charged separately. Two laps reverse optional/default backend order for each sparse `rare(_hit)+` and dense `dense_hit.+` content query.

Every sample opens fresh Truth, Log, View, RefHead and host; optional additionally opens fresh store/index/verifier, while default has no private verifier. Both backends carry the same real action ports and native Truth prefetch. The prepared artifact already exists. OS caches are warmed by seed/preparation, imports and the Node process are reused; these are fresh-handle prepared queries, not dropped-cache disk measurements. Full FaceResults must agree, all 512 eager info checks remain, and the optional sparse/dense controls prove one artifact read and one verified source. Sparse reaches EOF and installs a complete proof; dense stops early and installs none.

One bounded stdout line starts `FUGUE_COLD_DIAGNOSTIC` and contains a separate developer schema, raw times/Node CPU, setup/preparation costs, native counters, result hashes and source/test/corpus/artifact fingerprints. It leaves the frozen `ci-timing` schema1, artifact filenames and upload step untouched. Failure paths attempt every owned close and generated-directory removal; no workspace/user configuration is written.

The report checks actual production files against immutable checkout blobs before allocation and after queries. It records checkout HEAD/tree and only a validated optional PR head SHA from event metadata, without printing the event body or reading tokens. GitHub PR checkout normally uses a merge ref: after the run, compare reported tree and production hashes with the reviewed published head before attributing results to that head. A merge SHA alone is insufficient.

Checkout, fixture, Git-object and artifact filesystems are observed separately with statfs and optional findmnt. The ext-family magic alone does not identify ext4; `ext4:true` requires both corroborating observations. Local overlay/tmpfs smoke data cannot be called ext4 evidence. Node/Git/kernel/CPU and runner fields permit comparison across runs.

Hosted-runner measurements remain trends/regression evidence under ROADMAP §2. They do not become first-grade architecture constants, a universal cold50ms certificate or approval of default indexing. The initial local smoke establishes receipts and cleanup only; exact PR source/tree and CI results are recorded separately after publication.
