# 已准备索引的磁盘校验读数

状态：仅开发侧成本拆分。基于已审的`index-gram-facts`树，不接外部改动过的worker/store分支，
不改产品策略、格式或查询。顺带同步上游a5bd9b4的两张架构表渲染修复及对应CHANGELOG。

```sh
node tools/test-entry.js fast src/search/index-validation-instrument.test.ts
node tools/bench-index-validation.js
node tools/check-targets.js
node tools/check-events.js
```

探针独占生成512个Git blob，共16,037,600字节；真实对象先入Git，store用同一原字节
验证BlobId后建索引。参考来自原文本的完整`needle`包含判断，每趟核对32个精确命中ID，
不能以两趟同为零证明等价。准备花5288.973ms，包含对象写入/主线程构建/fsync；这不是
产品后台worker的准备速度。所有生成目录与Truth句柄都在finally收走。

每趟新建lookup、关闭facts、保留默认256条完整表预算，以四路并发读全部512条已准备
记录；缺失或坏表导致null即断言失败，source回调不准被调用。仍完整执行现有目录所有权/
权限/no-follow、文件前后stat、大小/格式/校验和/规范字节核对。每趟512次disk hit、零
source读取。刚写完文件且同进程重复运行，OS页缓存可能热；不是未准备的新源冷路径，
也不是包含View候选与正则验证的grep端到端读数。

三对交替读数（云overlay，同进程，毫秒）：

| 对 | 不包装API的墙钟 | 观察器墙钟 |
|---|---:|---:|
| 1 | 367.254 | 327.230 |
| 2 | 347.406 | 337.663 |
| 3 | 301.155 | 300.070 |

观察器只包本进程的标准fs open及返回句柄的stat/read/close，原参数、receiver、结果及
错误原样传递，完毕恢复open绑定，安装钩子失败也回滚绑定。已返回FileHandle的
方法包装不单独恢复：调用方必须先关完观察期句柄；探针逐条close并最终关闭lookup，
才恢复标准open，不向外借出这些句柄。不需要ptrace，不追其它进程，不把它称kernel syscall
计数。它增加Promise/时间戳/样本数组/调度开销，所以产品墙钟取单独未包装趟，观察器
不是另一种更快实现，包装趟偶尔更快也只说明共享机器/缓存/顺序等混杂仍在，不能当优化
收益。前一次未包装377–477ms的波动同样说明这里没有稳定的性能常数。API次数每趟稳定：open3072、stat3584、read1024、close3072，合计
10752；即每条6/7/2/6次。第一观察趟各操作的**重叠累计**时间为390.541/418.660/
140.232/738.251ms，远大于327.230ms墙钟：并发请求相互重叠，绝不能把它们相加分摊
墙钟百分比，也不能从close累计大就断言close是唯一瓶颈。

JSON记录探针及全部lookup依赖的SHA256、每对完整命中ID、预算/缓存统计与API分布。
决定：把“每条完整校验的API扇出”作为后续有界批量读取的待验证假说；减少次数并不自动
等于端到端变快。已有小组调度实验出现dense/sparse回退，仍保留不发布。下一步大组
32/128重放由独立实验验证，不能把这份观察器读数当收益。这里不修改事实缓存、信任
检查或默认档，未满足0.4的16MB冷路径<50ms，也没有一等档ext4验收。
