# Optional current-View cohort queries

`createViewCohortLookup(view, enumerate, store)` connects the bounded cohort artifact to the existing `grep` candidate seam (ROADMAP § 4 / 0.3.3). Pass the returned handle as `HostOptions.cohortIndex` to `createToolHost` for that exact View object. The adapter is privately bound to that object; another View or a caller-constructed port receives the existing scan path. The option is absent by default. If both index options are supplied, the valid cohort option takes precedence over `blobIndex`.

The first supported query in a View generation captures a bounded enumeration and its current file BlobIds, deduplicates the IDs, and reads one artifact for that exact set. Concurrent admitted queries share this load. Later batches reuse the one immutable handle; a miss is also retained until the generation changes, successful preparation occurs on this handle, or the caller creates a new handle. Any unavailable, corrupt, unsafe, over-budget or wrong-set artifact returns all original candidates. Queries never fetch source blobs, build, or publish an index.

Candidate decisions use current `view.stat` identities. Only strict negative membership excludes a file; unsupported requirements, missing metadata and files outside the artifact stay in the original ordered batch, including duplicate paths. Any base/rev change during enumeration, disk IO or metadata work restores the whole batch. A generation change starts a new artifact selection. This is a per-batch check, not an atomic snapshot of a whole multi-batch search; files added outside the original tool enumeration retain its existing coverage semantics. The original regex, real content reads, output modes, early stopping and incomplete-enumeration receipts remain authoritative.

Preparation is explicit caller-paid work: `await handle.prepare(readBlob)`. The callback selects immutable Git objects by complete BlobId, never materialized paths. Every source is copied from its intrinsic visible typed-array window and verified by `buildBlobIndex`; no subclass length/offset/buffer getter or iterator supplies a budget or content boundary. Complete verified records build one complete cohort. A failed source hash, generation change, unsupported source, dictionary/postings/byte cap, write failure or close returns false and never installs a partial membership proof. A successfully written old artifact may remain if the View changes during publication; its immutable ID-set key cannot be used as the new generation's artifact.

Bounds are independent: 5000 enumerated paths, 4096 distinct blobs, 128 paths/required UTF-16 trigrams per query batch, 64 MiB aggregate source windows during preparation, and the codec's 200,000 dictionary grams / 2,000,000 postings / 32 MiB artifact limits. Dense indexed snapshots capture and validate one safe-integer length; iterators and sparse inputs cannot enlarge admission. At most four operations are admitted, with no wait queue. One preparation is shared; invalid or saturated admission falls back. The retained artifact and in-flight records have additional decoded memory overhead, so the byte limits are not a whole-process heap bound.

`close()` immediately prevents new admission, drops the retained artifact and observes every accepted query/preparation until it settles. Source callbacks must settle; there is no hard cancellation of already-started source or filesystem IO. The caller separately owns `store.close()`, after closing the adapter. Preparation does synchronous codec work on the caller's execution thread and must be accounted outside the measured foreground query. `stats()` reports queries, artifact reads, source calls, builds, fallbacks and current admission; source calls do not imply a count of actual Git spawns.

The adapter tests cover a fresh one-artifact disk read, paid preparation, absent/throwing/wrong-set fallback, generation rollback, exact View branding, dense input ownership, one-length capture, intrinsic source-window admission, shared preparation and bounded close observation. The prior proxy-length negative control performed 10,000 indexed reads after admitting a one-element array; the repaired capture performs exactly one. Real View receipt equivalence and 16 MiB cold-path measurements are separate integrated acceptance. This implementation supplies no default-activation, <50 ms, genuine live recording or strict sandbox certificate.
